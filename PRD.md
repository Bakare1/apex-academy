# Product Requirement Document (PRD): DevForge Apex Academy

## 1. Executive Summary & Goal

**DevForge Apex Academy** is a cross-platform mobile application (built with Flutter) that delivers technical software development courses to students. The platform allows users to browse course offerings with dynamic pricing, securely pay via Paystack, auto-unlock course content upon payment confirmation, and watch structured course modules/lessons with role-gated access.

## 2. Target Audience & Roles

| Role | Responsibilities & Access |
| ----- | ----- |
| **Guest / Student (Unauthenticated)** | Browse catalog, view public course details, register, login. |
| **Student (Authenticated & Unenrolled)** | View profile, initialize Paystack payments for courses, access free preview content. |
| **Student (Authenticated & Enrolled)** | Full access to paid course lessons, sequence tracking, transaction history. |
| **Instructor / Admin** | Create/manage course lessons, manage student enrollments, view system analytics. |

## 4. Detailed Screen Requirements & Acceptance Criteria

### Screen 1: Course Catalog (Home)

* **Goal:** Display available technical courses with dynamic pricing and clear value propositions.
* **UI Elements:**
  * Top Search Bar & Category filters (e.g., *Flutter, Java Spring Boot, Python*).
  * Course Cards: Thumbnail image, title, instructor name, badge (*Enrolled* vs. Price Tag e.g., `₦25,000`), star rating.
  * Pull-to-refresh & skeleton loader states.
* **Backend Endpoint:** `GET /api/v1/courses`

### Screen 2: Course Detail Screen

* **Goal:** Convert students into buyers and present structured course breakdown.
* **UI Elements:**
  * Hero video preview/banner image.
  * Course metadata: Duration, level, total lessons, updated date.
  * **Dynamic Pricing Badge:** Display current price.
  * Curriculum Accordion: Expandable list of modules and lesson titles (locked icons for paid content).
  * **Primary Action CTA Button:**
    * If Unenrolled: **"Enroll Now — ₦XX,XXX"**
    * If Enrolled: **"Continue Learning"**

### Screen 3: Payment & Checkout Flow (Paystack Integration)

* **Goal:** Facilitate seamless and secure payment processing.
* **UI Elements:**
  * Order Summary breakdown (Course title, price, discount/tax if applicable).
  * Payment CTA Button: **"Proceed to Paystack"**.
  * **In-App WebView:** Opens Paystack checkout URL generated by backend.
  * Payment Processing / Status Screen: Loading spinner while webhook completes verification (`POST /api/v1/payments/initialize/{courseId}`).
  * Success / Failure Modal: Auto-redirects to Course Lesson Player upon success.

### Screen 4: Course Lesson Player Screen (Gated Access)

* **Goal:** Deliver video and text content cleanly to enrolled students.
* **UI Elements:**
  * Main Video Player / Content Viewport at the top.
  * Sequenced Lesson List below with completion checkboxes/status.
  * Next / Previous lesson navigation buttons.
* **Edge Case / Security UI Handling:**
  * If an unenrolled student attempts to access a locked lesson, display a clean modal/banner driven by the `403 Forbidden` JSON error:
    > **"Access Denied: You must be enrolled in this course to view its lessons."**

### Screen 5: Student Profile & My Courses

* **Goal:** Allow students to manage account settings and quickly access active courses.
* **UI Elements:**
  * Profile avatar, full name, email, and current role badge (`STUDENT`).
  * "My Enrolled Courses" tab.
  * Payment Transaction History log.
  * Logout CTA.

## 5. Technical Integration Specifications for Designers

### Standardized API Error Response Payload

Designers should account for standard error toasts/dialogs using this exact JSON structure from our backend `GlobalExceptionHandler`:

```json
{
  "timestamp": "2026-10-24T21:45:00.123456",
  "status": 403,
  "error": "Forbidden",
  "message": "Access Denied: You must be enrolled in this course to view its lessons.",
  "path": "/api/v1/lessons/course/1",
  "validationErrors": null
}
```
